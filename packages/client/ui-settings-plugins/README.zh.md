# dsh-client-ui-settings-plugins

[English](README.md) | 中文

**插件**设置分区。它拥有标题、引导语与标签栏外观；功能插件通过 `settings.plugins.tab` 贡献只读页面。本包自己不贡献任何页面。

## 这里会出现什么

本分区投影 `settings.plugins.tab` 账本——每个贡献页面的插件一条，按贡献的 `order` 排序、用注册方给出的标签——并挂载读取结果。今天这份账本只有一个页面：由 [`ui-settings-plugin-inventory`](../ui-settings-plugin-inventory/README.md) 注册的只读插件列表。

一个页面算不上选择，因此唯一的贡献会以普通标题呈现，而不是放进标签栏：只含一个按钮的标签栏会被读成“这里有个控件等你按”，而并没有别处可切。第二份贡献出现时，真正的标签栏就回来了；在标签栏里，某个页面首次被选择后才会挂载，隐藏时也保持挂载，因此页面的展开状态与搜索文本在切换时不会丢失。

## 这里没有配置功能

本部署的定制是服务器端的决定，只在服务器上改动。因此本分区不包含任何卡片、表单或写入路径：它过去自带的三个可编辑宿主平面卡片（`shell`、`agent-loop`、`web-search-deepseek`）已被删除，而不是藏在开关后面；它们所挂载的、以命名空间为键的 `settings.plugin.item` slot 也不再声明。

删除这些卡片不改变任何插件行为。那些 settings 命名空间由注册它们的插件拥有，而不是由这个页面拥有，默认值也未被触碰：shell 执行器保留 `timeoutMs` 120000 与 `maxOutputBytes` 64000（另有 `maxTimeoutMs` 600000、`maxSpillBytes` 64 MiB、`graceMs` 3000，这三项从未被卡片编辑过），agent 循环保留 `maxParallelToolCalls` 10，DeepSeek 搜索提供方保留 `maxUses` 5，其接口地址取自 `$DEEPSEEK_SEARCH_BASE_URL` 或 `https://api.deepseek.com/anthropic/v1`，密钥取自 `DEEPSEEK_API_KEY`。已经写入部署 settings 文档的值仍然生效，因为拥有它的插件无论浏览器里有没有卡片都会读取该文档；改动这样的值现在是服务器端的编辑。

## 扩展点

本分区声明根级列表 slot `settings.plugins.tab`，其标签会成为有序标签页。插件用 `ctx.slots.inject('settings.plugins.tab', …)` 贡献页面，并拥有该页面的组件、文案与数据——包括它是否只读。贡献页面除了已经拿到的 slot 声明之外，不需要依赖本包。

## 模型体验

无。本包只渲染浏览器外观，不写入任何内容，因此完全不触达模型。

#### KV Cache 影响

无；该包既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **本分区按设计不写入任何内容**——浏览器内的编辑路径需要一套面向用户自有插件设置的 Host 契约，外加一个负责暂存与 revision 设栅的包。两者现在都不存在，因此插件配置完全不再是浏览器能力。
- **唯一的贡献会去掉标签栏**——只有一个页面时，贡献的标签会变成普通标题。这正是“单一视图”应有的读法，但也意味着第二份贡献出现时外观会变一次形状。
- **访问过的页面保持挂载**——贡献的页面一旦被选择就保持挂载，以便其本地状态在切换标签时存活；因此读者访问过的每个页面都会一直活着，直到分区卸载。
