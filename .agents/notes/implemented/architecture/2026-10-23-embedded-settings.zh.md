# Agent Note: 嵌入式设置入口

Status: implemented

[English](2026-10-23-embedded-settings.md) | 中文

## 问题

e-server 嵌入外壳需要在每个应用中提供全局 Settings 操作，而目前唯一的触发按钮位于对话框架内。

## 决策

SettingsRoot 仅接受来自实际父窗口、且与 referrer 精确同源的打开和关闭命令，同时要求嵌入页面具有相同的主机名和协议。独立应用保留触发按钮，嵌入式应用则省略此按钮；打开和关闭操作仍写入现有外壳 store。

仅显示设置的框架与对话框架使用相同的设置区、偏好和源。它抑制引导流程并隐藏周围的应用，同时保持设置面板可见。ready 和 closed 消息让外壳管理加载状态并恢复焦点。这些消息不携带账户凭据。

## 影响

外壳可以从任意应用打开同一设置，而无需创建另一个偏好 store。组件测试覆盖消息来源与源检查、关闭和自动打开。e-server 浏览器测试覆盖对话框架和从另一个应用打开的设置框架。

## 考虑过的替代方案

复制设置表单会产生两套偏好实现。通过检查 DOM 来点击现有触发按钮会依赖呈现细节，并且无法跨源工作。限定的父窗口消息契约保留现有 actions 作为修改 API。
