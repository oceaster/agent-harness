# Agent Note: 部署人格默认值与工作代理策略

Status: implemented

[English](2026-10-11-deployment-personality-policy.md) | 中文

## Problem

部署可以选择人格预设，但 Web 会话仍可能使用全局模型默认值。切换模型后，子代理也可能继承创建时的旧选项。仅隐藏创建工具不能阻止服务调用方继续创建子代理。

## Decision

限定作用域的 `agent/default-model` 贡献为空会话提供默认值。选择器的显式选择与已记录请求头仍具有优先权。提示组装将所选提供方、模型和推理力度复制到代理选项，子代理组合继承这些选项。`AgentOptions.reasoningEffort` 为循环提供首次请求的推理力度。限定作用域的 `subagent/authorize` bail 事件在一次性和可继续委派分配资源前运行；返回原因会产生 `DELEGATION_DENIED`。CLI 启动保留配置的预设根目录。

Easter 部署通过 e-server 插件拥有人格文本、角色分配、工单工具与持久工单存储。Harness 仅拥有模型默认值与委派执行限制的扩展点。

## Alternatives considered

逐请求按人格路由会覆盖模型选择器，并使界面显示的选择具有误导性。仅靠提示词限制委派不能阻止直接服务调用。将全部工单和人格行为嵌入循环会把部署策略耦合到上游执行驱动器。

## Consequences

模型切换仍独立于人格。进程内工作代理继承实际组装的选择。默认值贡献是可选的，没有授权监听器的部署保留普通委派行为。策略拒绝在提供方调用与可继续代理资源预留之前执行。

针对性包测试覆盖默认值解析、继承和两条被拒绝的委派路径。组合部署 smoke 使用隔离目录与脚本化 LLM 启动真实构建的 Web profile，切换空会话人格，并执行从工作代理提交到协调者验收的工单委派流程。真实提供方响应与 GPU 推理需要独立的线上验证。
